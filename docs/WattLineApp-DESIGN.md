# WattLine Design

## 1. 제품 방향

WattLine은 한전 수목전지 현장에서 작업자가 사진을 촬영하고, 촬영 목적을 분류한 뒤 임시 저장하거나 서버로 업로드하는 모바일 우선 PWA입니다.

제품은 앱스토어 설치가 필요한 네이티브 앱이 아니라 HTTPS 주소와 홈 화면 설치를 사용하는 정적 PWA로 운영합니다. 현장 촬영 흐름을 빠르게 검증하고 Vercel에 가볍게 배포하는 것이 현재 단계의 목표입니다.

## 2. 목표

- 현장 작업자에게 빠르고 단순한 3-Tap UI 제공
- 촬영한 사진을 작업장·분류 기준으로 정리해 서버로 업로드
- 90cm 활선 접근 경고 및 수목 이격거리 기반 안전 가이드 표시
- 업로드된 사진을 서버 또는 Vercel Blob 기반 저장소에 전달(향후 연동)
- 본사 관제 센터와 연동 가능한 확장 구조 설계

## 3. 사용자

### 3.1 현장 작업자 / 반장

- 사진 촬영 및 분류
- 작업장명 입력
- 업로드 및 임시 저장
- 안전거리 정보 확인

## 4. 핵심 사용자 흐름

```text
앱 실행
  -> 작업장명 입력
  -> 촬영 버튼 클릭
  -> 앱 내부 카메라 미리보기 (확대·축소 가능)
  -> 사진 촬영
  -> 셔터음 재생
  -> 사진 분류 팝업 (분류별 현재 장수 표시)
  -> 분류 선택
  -> 찍힌 사진 목록 추가
  -> 임시저장 또는 전체 사진 업로드
```

카메라 권한이 거부되거나 `getUserMedia()`를 사용할 수 없는 브라우저에서는 스마트폰 카메라 앱을 여는 파일 입력 방식으로 fallback합니다.

## 5. 화면 순서

현재 화면(`index.html`)은 다음 순서로 구성합니다.

1. 상단 브랜드 영역: `W` 배지, `사진촬영` 제목, `refresh` 버튼, 앱 버전 표시
2. 작업장명 입력 카드
3. 현장 촬영 카드: 카메라 미리보기, 확대·축소, 촬영 버튼, 사진 분류 팝업
4. 사진 개수 요약 + 하단 액션 버튼(`임시저장`, `사진 업로드`)
5. 찍힌 사진 목록
6. 사진 미리보기 모달 (목록에서 `미리보기` 클릭 시 표시)
7. 활선 접근 제한 및 수목 이격거리 카드

PWA 설치 배너는 화면 흐름과 별개로 하단에 고정 오버레이로 표시됩니다(브라우저의 `beforeinstallprompt` 이벤트 발생 시).

## 6. 레이아웃 속성

### 6.1 앱 프레임

- 최대 폭: `420px`
- 데스크톱 최소 높이: `860px`
- 모바일 폭: `100%`
- 데스크톱 바깥 여백: `18px`
- 앱 프레임 모서리: `34px`
- 모바일 모서리: `0`
- 프레임 오버플로: `hidden`
- 모바일 하단 안전 영역: `env(safe-area-inset-bottom)`

### 6.2 간격과 모서리

- 기본 섹션 하단 여백: `16px`
- 카드 내부 패딩: `16px`
- 작은 버튼 모서리: `10px`
- 일반 카드 모서리: `22px`
- 촬영 스테이지 모서리: `18px`
- 사진 목록 항목 모서리: `0` (사각형)
- 촬영 버튼 크기: `110px × 110px`
- 하단 액션 버튼 높이: `52px`

- 시작전주: 청색 계열
- 종료전주: 녹색 계열

- 흉고직경: 청록·수목 계열
- 작업후: 황갈색·주황 계열
- 기타: 어두운 중성 계열

## 8. 타이포그래피

- 글꼴: Google Fonts `Inter`
- 기본 텍스트 색상: `#edf8ff`
- 보조 텍스트 색상: `#9ab2c2`
- 화면 제목: 굵은 `700~800`
- 버튼 텍스트: 굵은 `700~800`
- 작은 라벨: `10~12px`
- 본문 및 상태 텍스트: `12~14px`
- 작업장명 입력: `1.35rem`
- 작은 라벨은 대문자 표기와 `letter-spacing`을 사용해 상태 정보를 구분

## 9. 주요 컴포넌트

### 9.1 상단 브랜드 영역

- `W` 브랜드 배지 (로고 이미지 배경)
- 화면 제목: `사진촬영`
- 우측: `refresh` 버튼 + 앱 버전 표시(`#app-version`, `v0.1`부터 시작)

`refresh` 버튼은 현재 경로에 `refresh=타임스탬프` 쿼리를 붙여 브라우저 캐시를 우회합니다. 서비스 워커에도 `registration.update()`를 호출해 최신 리소스를 확인합니다. 앱 버전은 배포할 때마다 1씩 올립니다.

### 9.2 작업장명 카드

- 텍스트 입력(`#workplace-name`), placeholder `작업장명 입력`
- 입력값은 `localStorage`(`wattline-workplace-name`)에 저장되어 새로고침 후에도 유지
- 값이 비어 있으면 업로드/파일명 생성 시 기본값 `작업장`을 사용

### 9.3 카메라 촬영 영역

- `video` 요소 기반 앱 내부 카메라 미리보기
- `playsinline`으로 모바일 브라우저의 전체 화면 전환 방지
- 후면 카메라 선호: `facingMode: { ideal: "environment" }`
- 첫 번째 촬영 버튼 클릭: 카메라 권한 요청 및 미리보기 시작
- 두 번째 클릭: `canvas`로 현재 프레임 캡처
- 확대·축소: 기기가 네이티브 `zoom` capability를 지원하면 `track.applyConstraints`로 적용, 지원하지 않으면 CSS `transform: scale()`로 대체
- 촬영 버튼: 반투명 녹색 원형 배경
- 촬영 전에는 로고 이미지를 블러 처리한 배경을 보여주고, 미리보기 시작 시 영상으로 전환
- 카메라 사용 불가 시 `input[type=file][capture=environment]`로 fallback

### 9.4 촬영음

사진 캡처가 완료되면 Web Audio API로 짧은 셔터음을 생성합니다.

- 발진기 파형: `square`
- 시작 주파수: 약 `920Hz`
- 종료 주파수: 약 `180Hz`
- 재생 시간: 약 `0.1초`
- 사용자 클릭 이후에만 실행해 모바일 자동재생 제한을 피함

### 9.5 사진 분류 팝업

촬영 직후 화면 중앙에 모달 팝업을 표시합니다.

- 화면 전체 반투명 어두운 오버레이, 배경 블러 `3px`
- 팝업 최대 폭: `360px`, 모서리: `18px`
- 상단에 현재까지의 총 업로드(촬영) 장수 표시
- 분류 항목: 시작전주, 종료전주, 작업전, 흉고직경, 작업후, 기타 (2열 그리드)
- 각 분류 버튼 우측에 해당 분류의 현재 장수 표시
- 첫 번째 버튼에 자동 포커스
- 분류를 선택해야 사진이 목록 데이터에 추가되고, 선택 즉시 카메라 미리보기가 다시 시작됨

### 9.6 찍힌 사진 목록

사진이 한 장 이상 분류되면 하단 목록이 표시됩니다.

- 목록 제목: `찍힌 사진 목록`
- 우측 개수 배지: `n장`
- 목록 항목 구성: 번호·분류명, 썸네일, 액션 버튼
- 항목 모서리는 사각형(`border-radius: 0`)
- 최신 촬영 사진이 목록 맨 위에 표시됨(`createdAt` 기준 내림차순)
- 사진 데이터는 `localStorage`의 `wattline-captured-photos`에 저장되며 새로고침 후에도 복원됨

각 사진 항목의 액션:

- `미리보기`: 하단 사진 미리보기 모달에서 원본 이미지 확인
- `삭제`: 목록과 `localStorage`에서 삭제

### 9.7 사진 미리보기 모달

- 목록의 `미리보기` 버튼 클릭 시 표시되는 별도 모달(`#photo-preview-modal`)
- `role="dialog"`, `aria-modal="true"` 적용
- 닫기 버튼으로 모달을 닫으면 이미지 소스를 초기화

### 9.8 하단 액션

- `임시저장`: 현재 사진 데이터를 `localStorage`에 저장하고 사진 목록으로 스크롤 이동
- `사진 업로드`: 분류된 전체 사진을 한 번에 `/api/upload`로 전송, 진행 중 `업로드 중...` → 성공 `업로드 완료` / 실패 `업로드 실패`로 버튼 문구 변경
- 버튼 높이: `52px`, 모서리: `16px`, 두 버튼 동일 너비

### 9.9 작업장 정보 및 안전거리 카드

- 활선 접근 제한: `90cm` (고정 표시값)
- 수목 이격거리: `1.8m 이상` (고정 표시값)
- 접근 제한 진행 바: 주황색에서 녹색으로 이어지는 그라디언트
- 실시간 센서·거리 측정 연동은 아직 없으며, 향후 작업 항목임 (7절 참고)

### 9.10 PWA 설치 배너

- `beforeinstallprompt` 이벤트 발생 시 하단 고정 배너 표시
- `설치` 버튼: 표준 설치 프롬프트 표시, iOS 등 미지원 브라우저에서는 안내 alert(Safari 공유 → 홈 화면에 추가) 표시
- `닫기` 버튼: `localStorage`(`wattline-install-banner-dismissed`)에 저장해 이후 재표시하지 않음

## 10. 사진 데이터 흐름

```text
카메라 미리보기
  -> canvas 캡처 (확대 배율 반영해 크롭)
  -> 압축 (긴 변 1600px, JPEG 품질 0.8)
  -> 셔터음 재생
  -> 분류 팝업
  -> 분류 선택
  -> capturedPhotos 배열 (workplaceName, date, category, dataUrl, createdAt, fileName)
  -> localStorage 임시 저장 (wattline-captured-photos)
  -> /api/upload POST
```

브라우저 fallback 촬영에서는 선택한 파일을 `FileReader`로 Data URL로 변환한 뒤 동일한 압축·분류 흐름을 사용합니다. 필드 정의와 파일명 규칙의 상세 내용은 `HANDOFF.md` 6절을 참고합니다.

## 11. 서버 업로드 계약

클라이언트는 다음 형태로 전체 사진을 전송합니다.

```json
{
  "photos": [
    {
      "workplaceName": "작업장",
      "date": "20260917",
      "category": "작업전",
      "dataUrl": "data:image/jpeg;base64,...",
      "createdAt": "2026-09-16T00:00:00.000Z",
      "fileName": "20260917_123456_작업장_before-work_a1b2c3.jpg"
    }
  ]
}
```

요청 경로는 `POST /api/upload`입니다. `workplaceName`, `category`, `date`, `dataUrl`, `fileName`이 모두 문자열인 항목만 유효한 사진으로 처리하며, 하나도 없으면 `400`을 반환합니다. 현재 Vercel 함수는 요청 형식을 검증하고 수신 개수·분류 목록·파일명 목록을 반환합니다. 실제 영구 보관을 위해서는 Vercel Blob, S3 또는 별도 이미지 저장소 연결이 필요합니다.

## 12. PWA 및 브라우저 제약

- HTTPS 환경에서 카메라 권한을 요청해야 함
- `getUserMedia()` 지원 여부에 따라 카메라 앱 fallback 사용
- PWA 설치 프롬프트는 브라우저 정책에 따라 표시 여부가 달라짐
- 서비스 워커 등록 후 `registration.update()`로 업데이트 확인
- `refresh` 버튼은 캐시 우회용 URL을 생성
- 모바일에서는 Safari 또는 Chrome의 카메라 권한 설정이 필요

## 13. 접근성 및 상호작용

- 촬영 버튼과 하단 버튼은 큰 터치 영역 사용
- 카메라 미리보기와 팝업에 `aria-label`, `role`, `aria-modal` 적용
- 이미지에는 분류명 기반 대체 텍스트 적용
- 분류 팝업을 열 때 첫 버튼에 포커스 이동
- 위험 정보는 주황색과 강한 숫자 대비로 표시
- 삭제 액션은 붉은색 계열로 구분

## 14. 운영 원칙

- 앱은 모바일 현장 사용을 우선함
- 촬영·분류·저장·업로드 흐름을 한 화면에서 완료할 수 있어야 함
- 데스크톱은 개발 및 검수용 미리보기로 취급
- 배포는 사용자 요청이 있을 때만 실행하며, 배포할 때마다 앱 버전을 올림
- 카메라와 업로드 기능은 HTTPS 및 브라우저 권한 상태를 함께 확인해야 함
